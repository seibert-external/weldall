`weldall app` (singular) creates and publishes your own apps through your organisation's registry, without a Git account: `weldall app publish` creates the app on first use (`--name`, `--description`, `--share <permission>`, `--url`; repeating the same command after a stop continues with the same app), merges the repository's state, pushes one commit to a `weldall/publish-*` branch and opens or updates the pull request; `sync`, `status`, `list`, `confirm`, and for administrators `list --all`, `set-owner` and `checklist`. The CLI finds a registry only in Weldall's list (`registries` of `GET /api/me/apps`), never in a resource's own metadata, checks each entry against the resource's registration, sends git credentials only below a listed registry's git route, treats everything it reads back from the folder's `.git` as hostile (full object ids, bounded values, `--end-of-options` for git), renews an expired downstream token once, waits a short `Retry-After`, and explains every registry error in plain words. `weldall git-credential` is the credential helper git runs for that route. Without a registry, every `weldall app` command says that publishing is not set up. `weldall apps` (plural) accepts the new `registries` key and shows why Weldall refused a resource's apps API (`apps_api_refused`).
