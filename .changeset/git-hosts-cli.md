Add `weldall app publish`, `weldall app sync` and `weldall app status` to publish a locally built app through Weldall without a Git account. The repositories live behind a Git app, a separate service an organisation registers in Weldall as a resource (one per Git host); the CLI finds it in the resource registry Weldall lists for the person (scope `git-app:publish`), talks to it like to any registered resource (token exchange, downstream token, DPoP) and uses the only Git app the person may publish with, or the one `--git-app <resource key>` names. Publish merges the repository's state into the folder, pushes one commit through the Git app's git route and opens or updates a pull request; it stops on conflicts (exit code 3) and on files that look like secrets or data (exit code 4). Git settings and hooks in the app folder cannot make publish, sync or status start another program: git runs without the folder's hooks and fsmonitor, the steps that read or check out files, merge, fetch or push use a private git directory in `~/.weldall/git` instead of the folder's `.git/config`, and a folder whose git settings hold anything beyond what git and Weldall write there (for example a filter driver, another credential helper, or credential settings for another address than the Git app's), or that borrows git objects from another location, is refused before git touches it. The folder records its Git app, but a token or git credential only ever goes to the origin Weldall lists for it: a folder whose stored git URL points elsewhere is refused (`remote_untrusted`). Add `weldall git-credential`, the git credential helper git runs for a Git app's git route (it answers only for a Git app Weldall lists, stores nothing and never prompts), and `weldall app checklist` for administrators to run a Git app's set-up checklist against its Git host (exit code 3 when a required check fails). IaC accepts `github-app` and `forgejo` connectors with `github-app-private-key` and `forgejo-bot-token` shared connections and refuses them for servers without `git-hosts-v1`; the manifest JSON schema declares them. Add `weldall app list` (the person's apps in Weldall's app registry with their re-verification state and expiry) and `weldall app confirm [app]` (confirm that an app is still needed, which moves its expiry to 90 days from now). Without a registered Git app, or against an older server, the new commands fail with a clear message and change nothing.
