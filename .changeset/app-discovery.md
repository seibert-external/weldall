Resources can publish apps. A resource has a new switch, "Discover apps from this resource" (`appDiscoveryEnabled`, off by default, independent of skill and agent discovery). When it is on, Weldall reads the `weldall_apps_endpoint` named in the resource metadata with every catalog refresh (signed assertion of type `weldall-apps+jwt`, purpose `apps:read`, paged with `cursor`) and keeps a read-only copy: name, purpose, owner (if the resource reports one), the scopes the app is shared with, its repository (if it has one), the link where it runs (if any), and its created, last changed and review dates. An app past the review date the resource set is flagged "Review due" and is listed and linked as before. Links and repository URLs must be https URLs without credentials. The app side of a refresh has its own status, like the agent side: when the apps cannot be read or stored, the skills and agents are refreshed all the same and the last copy of the apps is kept for up to a day; a failure of the agents never affects the apps and vice versa. An app that fails validation is left out and counted (`apps_skipped`). The new `GET /api/me/apps` returns the apps the signed-in person owns or holds any one of the app's scopes for; Weldall's own system scopes never open an app, and an app without owner and scopes is seen by administrators only. Administrators see every discovered app under "Apps" (purpose, owner, email, shared with, resource, repository, link, catalog status, created, last changed, review date), and the resource page and list show the app discovery status, count and reload them. People find their apps on a new "Apps" tab of the directory, shown while a resource has app discovery switched on, with a page per app and an "Open app" link. Existing resources are unaffected.
