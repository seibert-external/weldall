Add the audit API for Git apps. A Git app is a separate service ([weldall-git-app](https://github.com/seibert-external/weldall-git-app)) that keeps the repositories of people's apps on a Git host and their app registry, and is registered in Weldall as a resource; Weldall itself never talks to a Git host and keeps no app records. A machine client with the new machine-only system scope `weldall:app-host` that is allowed for that resource reports the audit events of its apps (`POST /api/app-host/v1/audit-events`, idempotent per `eventId`, the person recorded as actor, the machine client as client and the Git app's resource as subject), announced as `weldall_app_host` in the OAuth metadata. The reported events are `git_repository.*` (including `git_repository.registered` for an existing repository an administrator registers), `git_push.*`, `git_fetch.*`, `git_pull_request.*`, `git_credential.*`, `git_host.checked` and `app_confirmation.*` (an owner's 90-day re-verification in the Git app's registry), with strict metadata schemas; an event names the app by the Git app's id and its repository. Credentials (such as Git host tokens, Git credentials, private keys and authorization headers) are now redacted from the metadata of every audit event before it is stored, not only from Git events, and from the server's logs. `POST /api/authorization/v1/check-scopes` now also answers `weldall:login` for a machine client with at least one allowed resource, so a Git app can stop serving a person who may no longer use Weldall. The database migration adds the new audit event types.
