Weldall tells clients which resources are app registries. A resource with app discovery switched on may name the API people's clients publish apps through in its metadata, `weldall_apps_api: { endpoint, scope, adminScope?, git?, gitCredentials? }`. Weldall reads it with every catalog refresh and passes it on only when it passes checks against the resource as registered in Weldall (endpoint an https URL on the resource's own origin without query or fragment ending in `/apps`; scope and admin scope the resource's own, different from each other and none of Weldall's system scopes; Git route exactly `<origin>/git/`; Git credentials endpoint an https URL on that origin). `GET /api/me/apps` gains `registries`: per such resource its key, name, resource identifier, endpoint, scope and admin scope, Git route and credentials endpoint, and whether the signed-in person holds each scope. A registry is listed while the metadata was read within the last day, whether or not its apps can be read and right after an administrator changed the resource, as long as it still passes the checks against the resource as it is now. An apps API that fails a check does not affect the apps, skills or agents; administrators see why on the resource page and as an `apps_api_refused` warning. Weldall stores the apps API whenever it can read the metadata, even when the skill catalog, the agents or the apps cannot be read, so a registry stays listed (and a withdrawn one is dropped) whatever happens to the other sides. Switching app discovery or the resource off clears it at once, so a resource switched on again is listed only after its metadata was read again. The app discovery switch says that it also lets the resource offer itself as a registry; the resource list shows which resources are listed as registries (**App registry**); and Weldall logs `app_registry.accepted`, `app_registry.changed` and `app_registry.withdrawn` with the resource key, endpoint and scopes. Unknown keys inside `weldall_agents_api` are now ignored instead of failing the agent side.
