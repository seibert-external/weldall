Resources can publish shared agents. A resource has a new switch, "Discover agents from this resource" (`agentDiscoveryEnabled`, off by default, independent of skill discovery). When it is on, Weldall reads the `weldall_agents_endpoint` named in the resource metadata with every catalog refresh (signed assertion of type `weldall-agents+jwt`, purpose `agents:read`, paged with `cursor`) and keeps a copy. The agent side of a refresh has its own status: when the agents cannot be read (no agent endpoint in the metadata, endpoint unreachable, assertion refused, malformed page), the skills are refreshed all the same, the last copy of the agents is kept for up to a day, and the resource page shows the agent failure. An agent that fails validation is left out and counted, and the rest is stored; administrators see the count on the resource page and as an `agents_skipped` warning. Each agent carries `createdAt` and `expiresAt` as the resource reports them. The new `GET /api/me/agents` returns the agents the signed-in person owns or holds any one of the agent's scopes for; Weldall's own system scopes never open an agent. Administrators see the discovered agents under "Shared agents" (who shared what with which scopes, created, last changed and expiry dates, and the status of the copy each comes from, without the agents' instructions), and the resource page counts and reloads them. People find the agents shared with them on a new "Agents" tab of the directory, shown while a resource has agent discovery switched on: cards filtered by who shared, resource and permission, and a page per agent with its instructions, starter questions, skills and connections, and its created, last changed and expiry dates. Existing resources are unaffected.
