Weldall native YAML infrastructure as code (IaC) gives platform teams a reviewable workspace for scopes, resources, machine clients, and assignments. The workspace is a `weldall.yml` file accompanied by the committed `weldall.lock.yml` lockfile. The lockfile records the server revision and object bindings so plans remain stable and recoverable.

## Quick start

Authenticate automation with a machine client. Register its public ES256 P-256 JWK and grant it the machine-only `weldall:iac` scope. Store the matching credentials in your CI secret store:

```sh
export WELDALL_M2M_CLIENT_ID=platform-ci
export WELDALL_M2M_KID=ci-2026
export WELDALL_M2M_PRIVATE_JWK='<private P-256 JWK JSON>'
export WELDALL_M2M_PUBLIC_JWK='<public P-256 JWK JSON>'
```

The private JWK belongs only in the secret store; the YAML manifest and lockfile contain public keys only. See [Machine authentication](/en/machine-authentication/) for key generation, registration, access, and rotation details.

```sh
weldall init --name platform-access --issuer https://weldall.example.com
weldall validate
weldall plan
weldall up --yes
```

`plan` is read-only and shows the deterministic changes. `up` applies one complete snapshot atomically; interactive runs ask for confirmation, while automation must pass `--yes`. Changes made in the admin UI to owned objects appear as drift and the next apply restores the YAML declaration. Objects not owned by this workspace remain independent.

## Ownership and recovery

Use `import` to explicitly claim an existing object by its natural identity. Use `unmanage` to release ownership while preserving the live object. A declaration removed from the YAML removes the owned object on apply; releasing it first keeps it in place. `state pull` reconstructs lockfile mappings from the authoritative server state after a failed local lockfile update. `state mv` changes a logical address without replacing the remote object.

## Commands

| Command                                           | Purpose                                        |
| ------------------------------------------------- | ---------------------------------------------- |
| `weldall init`                                    | Create a YAML workspace and lockfile.          |
| `weldall validate`                                | Validate and canonicalize YAML locally.        |
| `weldall plan`                                    | Preview deterministic changes.                 |
| `weldall plan --json`                             | Emit the plan as stable machine-readable JSON. |
| `weldall up`                                      | Apply after interactive confirmation.          |
| `weldall up --yes`                                | Apply non-interactively in CI.                 |
| `weldall import <kind> <identity> --as <address>` | Claim an existing object explicitly.           |
| `weldall unmanage <address> --yes`                | Release ownership and preserve the object.     |
| `weldall state pull`                              | Rebuild lockfile mappings from server state.   |
| `weldall state mv <old> <new>`                    | Move an address without replacing its object.  |

## Complete manifest example

This example uses every v1 primitive: scopes, a downstream resource with request prefixes and supported scopes, a machine client with an active public key and access, and email and group assignments.

```yaml
apiVersion: weldall.dev/v1alpha1
workspace:
  name: platform-access
  issuer: https://weldall.example.com
scopes:
  expenses_read:
    key: expenses:read
    description: Read expense reports
  expenses_submit:
    key: expenses:submit
    description: Submit expense reports
resources:
  expenses:
    key: expenses
    name: Expense service
    resourceIdentifier: https://expenses.example.com/
    authorizationServer: https://expenses.example.com
    downstreamClientId: weldall-platform
    enabled: true
    skillDiscoveryEnabled: true
    requestPrefixes:
      - https://expenses.example.com/api
    scopes:
      - expenses:read
      - expenses:submit
machines:
  platform_ci:
    clientId: platform-ci
    name: Platform CI
    enabled: true
    publicKeys:
      ci-2026:
        kty: EC
        crv: P-256
        alg: ES256
        use: sig
        x: IOqiZZjB6aPt6WuPSZw_sJxwdEueJ3AFo-AkI-c_sx0
        y: 8oDde4-gGqCC4jGY_vwNBbaAw8l4Xti8cv6NRtoinjk
    resources:
      - expenses
    scopes:
      - weldall:iac
      - expenses:read
emailAssignments:
  finance:
    email: finance@example.com
    scopes:
      - expenses:read
      - expenses:submit
groupAssignments:
  finance_team:
    provider: entra
    groupId: finance-team
    scopes:
      - expenses:read
      - expenses:submit
```

See the [manifest JSON Schema](https://github.com/seibert-external/weldall/blob/main/schemas/weldall-manifest-v1alpha1.schema.json), [IaC OpenAPI contract](https://github.com/seibert-external/weldall/blob/main/schemas/weldall-iac-v1.openapi.yml), and [implementation contract](https://github.com/seibert-external/weldall/blob/main/tasks/weldall-iac.md) for reference details.
