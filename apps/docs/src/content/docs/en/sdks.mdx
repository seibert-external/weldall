Weldall publishes two npm packages. The CLI runs on an employee's device. The SDK runs inside a connected service.

## `@weldall/cli`

[`@weldall/cli`](https://www.npmjs.com/package/@weldall/cli) installs the `weldall` command. Employees use it to sign in. Agents use it to discover skills and send approved requests to company services.

Choose either the JavaScript npm package (Node.js 22.15 or newer required) or a self-contained standalone executable (no Node.js, npm, Bun, or `node_modules` required). Both contain the complete CLI.

```sh
npm install --global @weldall/cli@latest
```

| System         | Supported release                | Architecture          | npm | Standalone archive    |
| -------------- | -------------------------------- | --------------------- | --- | --------------------- |
| Ubuntu Linux   | Current supported Ubuntu LTS     | x64                   | Yes | `linux-x64.tar.gz`    |
| Windows client | Windows 10 version 1809 or newer | x64                   | Yes | `windows-x64.zip`     |
| Windows Server | Windows Server 2019 or newer     | x64                   | Yes | `windows-x64.zip`     |
| macOS          | Current supported macOS releases | ARM64 / Apple silicon | Yes | `darwin-arm64.tar.gz` |
| macOS          | Current supported macOS releases | Intel x64             | Yes | `darwin-x64.tar.gz`   |

The Windows floor applies to both distributions and follows the stricter baseline needed by the Node.js 22 and embedded Bun 1.3 runtimes. Standalone assets are currently **unsigned**. They are not Apple-notarized or Authenticode-signed; installers, Homebrew, and WinGet are not provided. Download only from the scoped `@weldall/cli@X.Y.Z` GitHub Release and verify `SHA256SUMS` before replacing the executable.

POSIX example (select `linux-x64`, `darwin-arm64`, or `darwin-x64`):

```sh
VERSION=1.2.3
TARGET=linux-x64
ARCHIVE="weldall-v${VERSION}-${TARGET}.tar.gz"
BASE="https://github.com/seibert-external/weldall/releases/download/%40weldall%2Fcli%40${VERSION}"
curl -fLO "$BASE/$ARCHIVE" && curl -fLO "$BASE/SHA256SUMS"
EXPECTED="$(awk -v file="$ARCHIVE" '$2 == file { print $1 }' SHA256SUMS)"
if command -v shasum >/dev/null 2>&1; then
  ACTUAL="$(shasum -a 256 "$ARCHIVE" | awk '{print $1}')"
else
  ACTUAL="$(sha256sum "$ARCHIVE" | awk '{print $1}')"
fi
test -n "$EXPECTED" && test "$ACTUAL" = "$EXPECTED"
mkdir -p "$HOME/.local/bin"
tar -xzf "$ARCHIVE"
install -m 0755 weldall "$HOME/.local/bin/weldall"
```

PowerShell example:

```powershell
$Version = "1.2.3"
$Archive = "weldall-v$Version-windows-x64.zip"
$Tag = [uri]::EscapeDataString("@weldall/cli@$Version")
$Base = "https://github.com/seibert-external/weldall/releases/download/$Tag"
Invoke-WebRequest "$Base/$Archive" -OutFile $Archive
Invoke-WebRequest "$Base/SHA256SUMS" -OutFile SHA256SUMS
$Expected = ((Select-String SHA256SUMS -Pattern "^[0-9a-f]{64}  $([regex]::Escape($Archive))$").Line -split "  ")[0]
if ((Get-FileHash $Archive -Algorithm SHA256).Hash.ToLowerInvariant() -ne $Expected) { throw "Checksum mismatch" }
Expand-Archive $Archive .\weldall-release -Force
$Bin = "$HOME\bin"
New-Item -ItemType Directory -Force $Bin | Out-Null
Copy-Item .\weldall-release\weldall.exe "$Bin\weldall.exe" -Force
$UserPath = [Environment]::GetEnvironmentVariable("Path", "User")
if (($UserPath -split ";") -notcontains $Bin) {
  [Environment]::SetEnvironmentVariable("Path", "$Bin;$UserPath", "User")
}
$env:Path = "$Bin;$env:Path"
```

The user `Path` update persists for future Windows sessions. The `$env:Path` assignment affects only the current PowerShell process; open a new terminal when needed.

Upgrade npm installations with `npm install --global @weldall/cli@latest`. Upgrade standalone installations by checksum-verifying the new archive and replacing the executable.

The non-secret issuer preference is `~/.weldall/config.json` on Linux, `%USERPROFILE%\.weldall\config.json` on Windows, and the preserved `dev.seibert.weldall-cli/Issuer` defaults domain/key on macOS. Use `export WELDALL_ISSUER=https://weldall.example.com` in POSIX shells or `$env:WELDALL_ISSUER = "https://weldall.example.com"` in PowerShell for an ephemeral override.

Credentials and DPoP keys use Windows Credential Manager, macOS Keychain, or Linux Secret Service with a kernel keyutils fallback—never the issuer file. Ubuntu desktop users should unlock their login keyring. Headless Linux sessions need a user D-Bus session with an unlocked Secret Service (such as `gnome-keyring-daemon`) or a usable kernel keyring/keyutils environment; otherwise session commands fail closed with the backend error instead of storing plaintext credentials.

## `@weldall/sdk`

[`@weldall/sdk`](https://www.npmjs.com/package/@weldall/sdk) validates requests before a service reads data or makes changes. It provides a Fetch API and adapters for Hono, Next.js, and Astro.

```sh
pnpm add @weldall/sdk
```

Create one Weldall instance when the service starts:

```ts
import { initWeldall } from "@weldall/sdk";

const weldall = initWeldall("https://weldall.example.com", {
  resource: "https://contracts.example.com/api",
  publicOrigin: "https://contracts.example.com",
  clientId: "weldall-cli-at-contracts",
  supportedScopes: ["contracts:read", "contracts:update"],
  signingKey,
  replayStore,
});
```

In a Fetch handler, `weldall.verify(request, { scopes: [...] })` checks the request before business logic runs. Framework adapters provide middleware or handler wrappers:

- `@weldall/sdk/hono`
- `@weldall/sdk/next`
- `@weldall/sdk/astro`

The SDK requires Node.js 22.15 or newer. Next.js routes must use the Node.js runtime.

## Publish skills from a service

A resource can publish its own agent instructions. Add a `skills` provider to the same SDK configuration:

```ts
const weldall = initWeldall("https://weldall.example.com", {
  resource: "https://contracts.example.com/api",
  publicOrigin: "https://contracts.example.com",
  clientId: "weldall-cli-at-contracts",
  supportedScopes: ["contracts:read"],
  signingKey,
  replayStore,
  skills: {
    items: [
      {
        id: "list",
        title: "List contracts",
        requiredScopes: ["contracts:read"],
        visibility: "HIDDEN_IF_UNALLOWED",
        content:
          "# List contracts\n\nRun `weldall request --scope contracts:read https://contracts.example.com/api/contracts`.",
      },
    ],
  },
});
```

Skill IDs are local to the resource. If the registered resource key is `contracts`, Weldall exposes this skill as `contracts.list`.

Use `skills.load` instead of `skills.items` when the catalog comes from a database or another local source:

```ts
skills: {
  load: async () => loadPublishedSkills(),
}
```

The provider receives no employee identity. It must return the same catalog for every caller.

`DEFAULT` keeps a skill visible and reports missing scopes. `HIDDEN_IF_UNALLOWED` hides it unless the employee has every required scope. Visibility controls discovery, not authorization: the API route still needs its own protection policy, and skill instructions never grant access. Required scopes, including protected system scopes, must already exist in Weldall; unknown scopes are withheld from users and shown as warnings to administrators.

The Hono adapter mounts the catalog route through `weldall.registerRoutes(app)`. Fetch, Next.js, and Astro integrations must expose `weldall.handlers.skills` at `/.well-known/weldall-skills` alongside the OAuth metadata, token, and JWKS handlers.

See [How to: Integrate a service](../service-configuration/) for a complete Hono setup. [Security](../oauth-security/) covers keys, replay protection, and the protocol boundary.
