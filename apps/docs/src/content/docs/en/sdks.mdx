Weldall publishes two packages through npm. The CLI runs on an employee's device. The SDK runs in the connected company service.

## `@weldall/cli`

[`@weldall/cli`](https://www.npmjs.com/package/@weldall/cli) installs the `weldall` command. Employees use it to sign in. Agents use it to discover skills and send approved requests to company services.

:::note[Requirements]
The CLI currently supports macOS only and requires Node.js 22.15 or newer.
:::

```sh
npm install --global @weldall/cli
```

## `@weldall/sdk`

A downstream service must check incoming requests before it reads data or makes changes. [`@weldall/sdk`](https://www.npmjs.com/package/@weldall/sdk) provides JavaScript interfaces for Fetch, Hono, Next.js, and Astro.

:::note[Requirements]
The SDK requires Node.js 22.15 or newer. Next.js routes must use the Node.js runtime.
:::

```sh
pnpm add @weldall/sdk
```

Create a Weldall instance when the downstream service starts. It contains the service's public URL and the scopes accepted by its endpoints:

```ts
import { initWeldall } from "@weldall/sdk";

const weldall = initWeldall("https://weldall.example.com", {
  resource: "https://contracts.example.com/api",
  publicOrigin: "https://contracts.example.com",
  clientId: "weldall-cli-at-contracts",
  supportedScopes: ["contracts:read", "contracts:update"],
  signingKey,
  replayStore,
});

await weldall.ready(); // optional: validate the Weldall configuration at startup
```

In a Fetch handler, `weldall.verify(request, { scopes: [...] })` checks the incoming request before the business logic runs. The framework adapters perform this check through middleware or handler wrappers:

- `@weldall/sdk/hono`
- `@weldall/sdk/next`
- `@weldall/sdk/astro`

See [How to: Integrate a service](../service-configuration/) for the practical setup. [Security](../oauth-security/) explains keys, authorization, and the standards involved.
