Mit Weldall Native YAML Infrastructure as Code (IaC) verwalten Plattformteams Scopes, Ressourcen, Machine Clients und Zuweisungen in einem prüfbaren Workspace. Zum Workspace gehören `weldall.yml` und die versionierte Lockdatei `weldall.lock.yml`. Die Lockdatei speichert die Serverrevision und Objektbindungen, damit Pläne stabil und wiederherstellbar bleiben.

## Schnellstart

Automatisierungen authentifizieren sich mit einem Machine Client. Dafür wird dessen öffentlicher ES256-P-256-JWK registriert und der nur für Machines verfügbare Scope `weldall:iac` freigegeben. Die passenden Zugangsdaten werden im Secret Store der CI hinterlegt:

```sh
export WELDALL_M2M_CLIENT_ID=platform-ci
export WELDALL_M2M_KID=ci-2026
export WELDALL_M2M_PRIVATE_JWK='<privater P-256-JWK als JSON>'
export WELDALL_M2M_PUBLIC_JWK='<öffentlicher P-256-JWK als JSON>'
```

Der private JWK gehört ausschließlich in den Secret Store; YAML-Manifest und Lockdatei enthalten nur öffentliche Schlüssel. Die Seite [Machine-to-Machine-Authentifizierung](/machine-authentication/) beschreibt Schlüsselerzeugung, Registrierung, Zugriffsfreigabe und Rotation ausführlich.

```sh
weldall init --name platform-access --issuer https://weldall.example.com
weldall validate
weldall plan
weldall up --yes
```

`plan` verändert nichts und zeigt die deterministischen Änderungen. `up` wendet einen vollständigen Snapshot atomar an. Interaktive Aufrufe fragen nach einer Bestätigung, Automatisierungen übergeben `--yes`. Änderungen an verwalteten Objekten in der Admin-Oberfläche erscheinen als Drift; das nächste Apply stellt die YAML-Deklaration wieder her. Objekte außerhalb dieses Workspaces bleiben unabhängig.

## Ownership und Wiederherstellung

Mit `import` wird ein vorhandenes Objekt anhand seiner natürlichen Identität ausdrücklich übernommen. `unmanage` gibt die Ownership frei und erhält das Live-Objekt. Wird eine Deklaration aus dem YAML entfernt, löscht das nächste Apply das verwaltete Objekt; vorheriges Freigeben erhält es. `state pull` rekonstruiert die Lockdatei-Bindungen aus dem maßgeblichen Serverzustand, wenn ein lokales Lockdatei-Update fehlgeschlagen ist. `state mv` ändert eine logische Adresse, ohne das entfernte Objekt zu ersetzen.

## Befehle

| Befehl | Zweck |
| --- | --- |
| `weldall init` | YAML-Workspace und Lockdatei anlegen. |
| `weldall validate` | YAML lokal validieren und kanonisieren. |
| `weldall plan` | Deterministische Änderungen in der Vorschau anzeigen. |
| `weldall plan --json` | Plan als stabiles, maschinenlesbares JSON ausgeben. |
| `weldall up` | Nach interaktiver Bestätigung anwenden. |
| `weldall up --yes` | In der CI ohne Interaktion anwenden. |
| `weldall import <type> <identity> --as <address>` | Vorhandenes Objekt ausdrücklich übernehmen. |
| `weldall unmanage <address> --yes` | Ownership freigeben und Objekt erhalten. |
| `weldall state pull` | Lockdatei-Bindungen aus dem Serverzustand neu aufbauen. |
| `weldall state mv <old> <new>` | Adresse ändern, ohne das Objekt zu ersetzen. |

## Vollständiges Manifestbeispiel

Dieses Beispiel enthält alle v1-Grundelemente: Scopes, eine Downstream-Ressource mit Request-Präfixen und unterstützten Scopes, einen Machine Client mit aktivem öffentlichen Schlüssel und Zugriffsrechten sowie Zuweisungen für E-Mail-Adressen und Gruppen.

```yaml
apiVersion: weldall.dev/v1alpha1
workspace:
  name: platform-access
  issuer: https://weldall.example.com
scopes:
  expenses_read:
    key: expenses:read
    description: Read expense reports
  expenses_submit:
    key: expenses:submit
    description: Submit expense reports
resources:
  expenses:
    key: expenses
    name: Expense service
    resourceIdentifier: https://expenses.example.com
    authorizationServer: https://expenses.example.com
    downstreamClientId: weldall-platform
    enabled: true
    skillDiscoveryEnabled: true
    requestPrefixes:
      - https://expenses.example.com/api
    scopes:
      - expenses:read
      - expenses:submit
machines:
  platform_ci:
    clientId: platform-ci
    name: Platform CI
    enabled: true
    publicKeys:
      ci-2026:
        kty: EC
        crv: P-256
        alg: ES256
        use: sig
        x: IOqiZZjB6aPt6WuPSZw_sJxwdEueJ3AFo-AkI-c_sx0
        y: 8oDde4-gGqCC4jGY_vwNBbaAw8l4Xti8cv6NRtoinjk
    resources:
      - expenses
    scopes:
      - weldall:iac
      - expenses:read
emailAssignments:
  finance:
    email: finance@example.com
    scopes:
      - expenses:read
      - expenses:submit
groupAssignments:
  finance_team:
    provider: entra
    groupId: finance-team
    scopes:
      - expenses:read
      - expenses:submit
```
