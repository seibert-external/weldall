## Die zwei Hauptkomponenten

<CardGrid>
  <Card title="Weldall Authorization Server" icon="approve-check-circle">
    Authentifiziert den Benutzer, wendet zentrale Richtlinien an und stellt einen zielgebundenen
    Identity Assertion JWT Authorization Grant (ID-JAG) aus. Außerdem veröffentlicht er die
    Ressourcen-, Scope- und Skill-Register, die von der CLI verwendet werden.
  </Card>
  <Card title="Weldall CLI" icon="seti:shell">
    Ein nativer OAuth-Client für macOS. Er verwahrt den Geräteschlüssel im System-Schlüsselbund,
    bezieht DPoP-gebundene Zugangsdaten und ruft registrierte APIs direkt auf.
  </Card>
</CardGrid>

## Zusammenspiel der Komponenten

```text
Weldall CLI ── Anmeldung und Zugriffsanfrage ──▶ Weldall Authorization Server
     │                                                   │
     │                                                   └── stellt einen ID-JAG aus
     │
     ├── tauscht den ID-JAG beim Authorization Server der Ressource ein
     └── ruft die API direkt mit einem DPoP-gebundenen Access Token auf
```

So kann eine Vertrauensdomäne Identität und Autorisierung in eine andere übertragen, ohne dem Client wiederverwendbare Bearer-Zugangsdaten auszuhändigen oder den API-Verkehr durch Weldall zu leiten.

## Die Spezifikationen

Die Architektur folgt [OAuth Identity and Authorization Chaining Across Domains](https://datatracker.ietf.org/doc/draft-ietf-oauth-identity-chaining/). Die aktuelle Implementierung verwendet diese Draft-Versionen:

- [Identity Assertion JWT Authorization Grant, Draft 04](https://datatracker.ietf.org/doc/html/draft-ietf-oauth-identity-assertion-authz-grant-04) definiert den von Weldall ausgestellten ID-JAG.
- [OAuth 2.0 JWT Authorization Grant with DPoP Binding, Draft 01](https://datatracker.ietf.org/doc/html/draft-parecki-oauth-jwt-dpop-grant-01) definiert, wie dieser Grant gegen ein schlüsselgebundenes Access Token eingetauscht wird.

Der Ablauf verwendet außerdem [DPoP](https://www.rfc-editor.org/rfc/rfc9449), [OAuth 2.0 Token Exchange](https://www.rfc-editor.org/rfc/rfc8693), [Authorization Server Metadata](https://www.rfc-editor.org/rfc/rfc8414) und [Protected Resource Metadata](https://www.rfc-editor.org/rfc/rfc9728).
