Ein Skill in Weldall sollte in aller Regel eine **Handlungsanweisung für einen Agenten** sein. Er beschreibt einen konkreten Vorgang, den der Agent entweder:

1. über eine geschützte Unternehmensschnittstelle, also eine Weldall Resource, ausführt oder
2. bei fehlender Schnittstelle den Mitarbeitenden in den Browser führt oder einen Ansprechpartner nennt.

Wird der zweite Fall häufig genutzt, kann es sich lohnen, daraus eine Weldall Resource zu machen.

Ein Skill ist kein statisches Wissen, also Unternehmensinformationen, die sich selten ändern. Diese können in einer externen Dokumentation leben, zum Beispiel in Confluence oder einer statischen Wissenssammlung wie Starlight.
